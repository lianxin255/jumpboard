# Nginx 跳板机管理工具 — UI 设计需求文档

> 供 UI 设计师重新设计一版界面使用。本文档只讲「产品是什么、有哪些功能、每个功能要解决什么问题、设计师在设计时需要关注哪些点」，**不限定具体视觉风格**（视觉留给你发挥）。

---

## 一、产品一句话定位

一个**桌面端 GUI 工具**，让运维/开发人员不用写 nginx 配置、不用敲命令，点点鼠标就能把**内网里的服务**（数据库、Web、SSH 等）通过**这台机器（跳板机）**暴露给外网访问。可以理解为「nginx 的图形化遥控器 + 端口转发管理器」。

典型用户场景：
- 公司内网有一台 MySQL（192.168.1.10:3306），外面访问不了 → 用本工具在跳板机开个 9000 端口转发进去，外网连 `跳板机IP:9000` 就等于连到内网 MySQL。
- 内网有个 Web 服务 → 用本工具反代出去，还能上 HTTPS、做健康检查。

---

## 二、平台 & 形态

| 项 | 说明 |
|---|---|
| 平台 | Windows + macOS 双平台桌面应用（Electron） |
| 形态 | **绿色免安装**：Windows 是一个单独的 `.exe`（双击即用，不写注册表）；macOS 是 `.dmg` |
| 自带 nginx | 软件内置 nginx 二进制，用户不用自己装 |
| 数据存储 | 本地 SQLite，**退出不留痕**（数据存在程序旁边，拷走即用） |
| 窗口 | 单窗口桌面应用，**非**网页、**非**移动端 |

---

## 三、全局信息架构（5 个一级页面）

整个应用就 5 个主页面，通过顶部导航切换：

1. **映射**（核心页，默认页）— 管理所有「端口转发规则」
2. **日志** — 看运行日志和 nginx 日志
3. **历史** — 配置版本历史，可回滚
4. **主机** — 管理「在哪台机器上跑 nginx」（本机 / 远程 SSH 服务器）
5. **设置** — 数据导入导出、清空、关于

外加 2 个浮层：
- **模板选择器**（新建映射时先选模板）
- **映射表单**（填具体参数）

---

## 四、核心概念（设计师必须先理解）

在动手前，请先理解这 3 个概念，它们决定了界面怎么组织：

### 1. 主机（Host）
= 「nginx 跑在哪台机器上」。分两种：
- **本地主机**：nginx 就跑在本软件所在的这台电脑上（最常见）
- **远程主机**：通过 SSH 连过去，操控远程服务器上的 nginx

一个软件里可以管理**多个主机**，顶部有个主机切换器。所有映射/日志/历史都是**按主机隔离**的。

### 2. 映射（Mapping）
= 一条「端口转发规则」。这是产品的核心对象。核心字段：
- **规则名称**：用户自己起的名字，如「公司 MySQL 对外」
- **协议**：tcp / udp / http / https 四选一
- **监听端口**（listenPort）：跳板机上对外开放的端口，如 9000
- **内网服务 IP**（upstreamHost）：要转发的内网服务地址，如 192.168.1.10
- **内网服务端口**（upstreamPort）：内网服务真实端口，如 3306
- **启用开关**：每条规则可单独开关

不同协议还有各自的高级字段（HTTPS 要证书、HTTP 有域名和路径、所有协议都能配健康检查）。

### 3. 引擎（Engine）
= 「nginx 进程本身」。顶部有引擎控制条，显示 nginx 当前是**运行中 / 已停止 / 未知**，并提供「启动 / 应用配置 / 停止」三个动作。
- 关键认知：**改了映射不会立即生效**，要点「应用」才会重新加载 nginx 配置。这个「待应用」状态需要在 UI 上让用户感知到。

## 五、各页面详细需求

### 页面 1：映射列表（核心页，最重要）

**目标**：一眼看清「我现在有哪些转发规则，各自什么状态」，并能快速增删改、开关。

**需要展示的信息（每条规则）**：
- 规则名称
- 协议类型（tcp/udp/http/https，建议用不同颜色/图标区分）
- 转发关系可视化：`外部 → :9000 → 192.168.1.10:3306`（这条最关键，要让用户秒懂「谁转发给谁」）
- 启用/停用开关
- 健康检查状态（healthy / unhealthy / unknown）—— 如果开启了健康检查才有
- 最后修改时间

**操作**：
- 新建（→ 先弹模板选择器）
- 编辑（→ 弹映射表单）
- 删除（需二次确认）
- 单条启用/停用开关

**页面级**：
- 空状态：还没有任何规则时，引导用户「从模板创建」
- 顶部引擎状态条（运行中/停止 + 启动/应用/停止按钮）—— 最好让用户意识到「有改动未应用」

> 🎨 **设计重点**：转发关系 `:9000 → 192.168.1.10:3306` 的可视化表达是这个产品最核心的信息，建议重点设计。协议类型用图标+色彩区分会有助识别。

---

### 页面 2：日志

**目标**：排查问题时看日志。两类日志放两个 Tab：

**Tab A - 操作日志（app）**：软件自己记的操作日志，如「启动引擎」「应用配置」「回滚到 xxx」。
- 字段：时间、级别（info/warn/error，用颜色区分）、消息
- 可按级别过滤 + 关键字搜索

**Tab B - Nginx 运行日志**：分 error 日志 和 access 日志。
- 字段：时间、消息
- 可按级别过滤 + 关键字搜索
- 日志用等宽字体

**操作**：刷新按钮

> 🎨 **设计重点**：日志是大量文本，可读性 + 过滤效率是关键。级别用色块/标签区分（info 中性、warn 黄、error 红）。时间戳建议相对时间+绝对时间。

---

### 页面 3：配置历史（版本管理）

**目标**：每次「应用配置」都会存一个快照，出问题能回滚。类似 Git 的提交历史。

**布局**：左右分栏（master-detail）
- **左栏**：快照列表，每条显示「时间 + 操作原因（如"应用配置"、"手动回滚"）」
- **右栏**：选中某条后，展示该快照的 nginx 配置原文（代码块，等宽字体）

**操作**：
- 选中某条查看内容
- 「回滚到此版本」按钮（需二次确认，危险操作）

> 🎨 **设计重点**：左栏时间线感、右栏代码 diff 友好的展示。回滚是危险操作，确认态要醒目。

---

### 页面 4：主机管理

**目标**：管理「nginx 跑在哪台机器」。

**列表展示**：每个主机显示
- 名称
- 类型（本地 / 远程，用图标区分）
- 是否默认主机（标记）
- 引擎状态

**新增/编辑表单字段**（按类型不同）：

**本地主机**：
- 名称
- nginx 路径（可空，空=用内置）
- 配置目录（可空，空=用默认）
- 日志目录（可空）

**远程主机（SSH）**：
- 名称
- SSH 地址（host）
- SSH 端口（默认 22）
- 用户名
- 认证方式（密码 / 密钥）二选一
  - 密码：密码输入框
  - 密钥：密钥文件路径
- 远程 nginx 路径
- 远程配置文件路径
- reload 命令（默认 `nginx -s reload`）
- test 命令（默认 `nginx -t`）

**操作**：新增、编辑、删除、测试连接（远程主机）、设为默认

> 🎨 **设计重点**：本地 vs 远程两种形态差异大，表单要能平滑切换。远程 SSH 表单字段多，注意分组（连接信息 / 认证 / nginx 路径）。密码字段要安全。

---

### 页面 5：设置

**目标**：数据管理和关于信息。相对次要的页面。

**内容**：
- 数据导出（把所有主机+映射+配置导出成一个文件，方便迁移）
- 数据导入（从导出文件恢复）
- 清空所有数据（危险操作，强确认）
- 关于：软件名、版本号、内置 nginx 版本

> 🎨 **设计重点**：危险操作区要和普通操作视觉隔离。导入/导出是低频功能，不必太抢眼。

---

### 浮层 A：模板选择器

**目标**：新建映射时，先让用户选一个模板快速起步（而不是从零填表单）。

**13 个内置模板**，按分类分组：

| 分类 | 模板 |
|---|---|
| 网络层 | TCP 转发、UDP 转发 |
| Web | HTTP 网站、HTTPS 网站、WebSocket |
| 数据库 | MySQL(3306)、PostgreSQL(5432)、Redis(6379)、MongoDB(27017) |
| 远程访问 | SSH(22)、RDP(3389) |
| 消息 | MQTT(1883) |
| API | API 网关 |

每个模板卡片显示：**图标 + 名称 + 一句话描述**。

**操作**：选中模板 → 进入映射表单（预填好模板字段）。也支持「自定义」（空白表单）。

> 🎨 **设计重点**：模板卡片网格要直观，图标是主要识别元素。分类分组帮助用户快速定位。这是「降低使用门槛」的关键入口，值得重点设计。

---

### 浮层 B：映射表单

**目标**：填写/编辑一条转发规则的具体参数。这是字段最多的表单。

**基础字段（所有协议）**：
- 规则名称（必填）
- 协议选择（tcp/udp/http/https，**选了会动态改变下面的字段**）
- 内网服务 IP（必填）+「本机 IP」快捷选择按钮（列出本机所有网卡 IP）
- 内网服务端口（必填）

**按协议动态显示**：
- **TCP/UDP**：监听端口（必填）
- **HTTP**：监听端口、域名(serverNames)、监听路径(listenPath)
- **HTTPS**：监听端口、域名、监听路径、SSL 证书路径（必填）、SSL 私钥路径（必填）、HTTP→HTTPS 自动跳转开关

**高级配置（可折叠，所有协议都有）**：
- 自定义 nginx 指令（多行文本，给高级用户直接写）
- 健康检查开关 + 检查间隔 + 检查路径 + 期望状态码

**底部**：保存 / 取消。保存前会检测端口是否被占用，占用则提示。

> 🎨 **设计重点**：
> - 协议切换导致字段动态变化，过渡要平滑，别让布局跳。
> - 「内网服务 IP」+「本机 IP 快捷选择」是个高频交互，要顺手。
> - 高级配置默认折叠，别吓到新手。
> - 必填项校验反馈要清晰。

---

## 六、跨页面的全局元素

### 顶部导航栏（所有页面常驻）
- 应用标题/Logo
- **主机切换器**（下拉，选当前操作哪台主机）—— 显示主机**名称**（注意：不能显示成内部 ID/UUID，这是历史 bug）
- 主导航（5 个页面的 Tab）
- **引擎控制条**（状态指示灯 + 启动/应用/停止按钮）—— 放在右侧显眼位置

### 反馈与确认
- 所有删除/回滚/清空等不可逆操作 → 二次确认弹窗
- 操作成功/失败 → 轻量提示（Toast）
- 危险操作 → 红色/警示色 + 明确后果说明

---

## 七、状态体系（设计师需要用色彩/图标表达的）

| 状态 | 出现位置 | 建议表达 |
|---|---|---|
| 引擎运行中 | 顶栏 | 绿色亮点 + "运行中" |
| 引擎已停止 | 顶栏 | 红色/灰点 + "已停止" |
| 引擎未知 | 顶栏 | 灰点 + "未知" |
| 映射已启用 | 映射列表 | 开关 on / 高亮 |
| 映射已停用 | 映射列表 | 开关 off / 置灰 |
| 健康检查健康 | 映射列表 | 绿色 |
| 健康检查异常 | 映射列表 | 红色 |
| 健康检查未知 | 映射列表 | 灰色 |
| 协议 TCP/UDP | 映射列表 | 图标区分（tcp/udp 偏「传输层」感） |
| 协议 HTTP/HTTPS | 映射列表 | 图标区分（http/https 偏「Web」感，https 带锁） |
| 日志 info/warn/error | 日志页 | 中性 / 黄 / 红 |

## 八、给设计师的自由度说明

**以下由你决定**（不限定）：
- 整体视觉风格、配色、圆角、阴影、间距体系
- 具体图标选择
- 毛玻璃 / 拟物 / 扁平 / 暗色优先 等风格取向
- 具体布局结构（左右栏 / 上下栏 / 卡片网格密度等）
- 动效与微交互

**以下请遵守**（产品硬约束）：
- 必须是**桌面端**交互范式（鼠标为主， hover/右键/快捷键可用），不要做成移动端
- 5 个一级页面的信息架构不能合并/删减
- 映射列表里「转发关系 `端口 → IP:端口`」必须清晰可见
- 主机切换器必须显示主机名称
- 所有不可逆操作必须有二次确认
- 等宽字体用于：nginx 配置原文、日志内容
- 协议、健康状态、日志级别 需要用**色彩/图标**做区分，不能全靠文字

## 九、交付物建议

1. **5 个主页面** + **2 个浮层** 的高保真设计稿
2. **关键状态**的标注（运行/停止、启用/停用、各健康状态、各协议）
3. **空状态**设计（映射列表为空时）
4. **设计规范**：色彩、字体、间距、组件（按钮/开关/输入/卡片/表格/弹窗）规范
5. 暗色模式 + 浅色模式（如时间允许，暗色优先，符合运维工具调性）
