# JumpBoard UI 重设计 · 交付说明

## 方向

克制、清晰的专业网络工作台。不是更花哨的控制台，而是让规则状态、转发关系与下一步操作始终明确。保留现有六个页面与业务能力，未添加新功能或开关。

## 六页重排

| 页面 | 布局 | 解决的问题 |
| --- | --- | --- |
| 映射 | 完整场景下拉与创建一行，搜索与筛选拆分，分组芯片独立一行，单表格工作面 | 主次混乱、状态重复、场景选择器残缺 |
| 日志 | 类型/级别/导出独立工具区，稳定日志流 | 工具混排、内容边界不清 |
| 配置历史 | 左侧快照，右侧配置与差异，回滚靠近对象 | 只有列表没有工作上下文，空白浪费 |
| 终端 | 会话类型与新建在上，会话标签、终端和状态栏一体 | 空状态占据大卡片，会话缺少工作台骨架 |
| AI 对话 | ≥1120px 对话与待审草稿双栏；<1120px 回落单列。修改草稿显示字段级旧值/新值差异；支持重试复制、场景历史与冲突反馈 | 只能新增不能修改；对话不可恢复；失败难以重试；清空入口偏远且过重 |
| 设置 | 左分组导航，右侧一次一组表单 | AI 占据首屏，多卡片堆叠、阅读顺序跳跃 |

## 实施边界

这是 HTML/React 高保真方案，不进入生产构建。JumpBoard 生产界面仍为 Go + mygo；不引入 Electron、Chromium 或 Node 运行时。组件、令牌和交互契约可逐页映射到现有 `internal/ui/`。

- 服务状态唯一放在侧栏底部，启停仍保留确认。
- 页面级动作在窗口栏；搜索与状态筛选在工具区；分组筛选是独立一行的芯片；对象操作在对象行。
- 单面板工作面；弹窗单层表面；危险操作明确说明后果。
- 亮暗主题均使用语义色；危险实色按钮与危险文字分开定义。暗色正文、说明与辅助文字分层，输入框和关闭开关保留可见边界。
- 所有可点控件共享 hover / pressed / focus / disabled 规则；选中与悬停不是同一种颜色。
- 场景菜单显示规则数与当前标记；未应用改动保留在原场景。预检、应用、服务启停和 AI 测试连接都有进行中状态，并禁止重复提交。
- 断点：1120px 为 AI 双栏分界；1180px 映射地址改完整双行；960px 侧栏收为图标导航、设置改上下分组。
- 1000px 窄窗口下映射地址完整双行显示；不靠缩小字号换空间。
- AI 隐私边界：当前场景规则摘要随请求发送，便于修改现有规则；不包含 API Key。历史本地保存与发送轮数分开控制。
- 修改草稿必须绑定现有规则，冲突时禁止写入；新增/修改均须人工审阅，写入后再应用。
- 复制只含可读正文；重试不重复添加用户消息；清空只影响当前场景，普通次级按钮位于对话标题栏。

## 验证

- 设计系统编译与只读检查：12 组件、18 示例卡、128 令牌，无检查问题。
- 尺寸验证：映射页所有文字按钮、场景选择、紧凑搜索和分段器均实测为 32px；输入框/选择器 36px、开关 36×22、芯片 26px，均由统一令牌控制。
- 浏览器检查：六页直达、亮色/暗色、1000px 窄窗口、场景下拉与切换确认、预检/应用过程、服务启停、AI 双栏、设置分组。
- 交互原型 HTTP 预览无脚本错误；总览页无脚本或资源错误。
- 未修改或测试生产 Go 界面：本轮只更新设计稿与规范，等待确认后再实现。

## 建议评审顺序

先看映射页的表格与工具区，再看 AI 双栏和设置分组；最后比较亮暗主题。确认方向后再按“全局框架 → 映射 → 设置 → AI → 其余页面”的顺序实施。
